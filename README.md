# Astana Hub daily reward

Ежедневный вход в Astana Hub по email и паролю с получением награды. Сценарий запускается через GitHub Actions и не требует включённого пользовательского компьютера.

## Требование к аккаунту

Astana Hub должен разрешать вход по постоянному паролю. Если для email включён OTP, workflow остановится: одноразовый код нельзя получить автономно без отдельной интеграции с почтой.

## Настройка репозитория

1. Откройте `Settings → Secrets and variables → Actions`.
2. Создайте два repository secret:
   - `ASTANAHUB_EMAIL` — email аккаунта Astana Hub;
   - `ASTANAHUB_PASSWORD` — пароль аккаунта Astana Hub.
3. Откройте вкладку `Actions`, выберите `Astana Hub daily reward` и нажмите `Run workflow` для ручной проверки при необходимости.

## Как работает расписание

GitHub Actions запускает лёгкую проверку каждые 5 минут. Эта проверка читает журналы в папке `logs` и находит время последней строки `Награда: получена`.

Пока с момента последнего успешного получения награды не прошло 24 часа, браузер не запускается, Playwright не устанавливается и авторизация в Astana Hub не выполняется.

Как только прошло 24 часа, ближайшая пятиминутная проверка запускает браузер, выполняет авторизацию и пытается получить награду. Если награда ещё недоступна, запись `Награда: не доступна` не сбрасывает 24-часовой таймер, поэтому следующая попытка выполняется на следующем запуске GitHub Actions — примерно через 5 минут. После строки `Награда: получена` начинается новый отсчёт 24 часов именно от фактического времени успешного получения.

Например, если награда получена `16.09.2026 11:43:31 +0500`, первая следующая попытка будет выполнена на ближайшей пятиминутной проверке после `17.09.2026 11:43:31 +0500`. GitHub может запускать запланированные задания с задержкой, поэтому фактическое время может быть немного позже.

## Логи

После каждой реальной попытки авторизации workflow добавляет в папку `logs` местное время, результат авторизации и состояние награды. Лёгкие проверки, при которых 24 часа ещё не прошли, в журнал не записываются. Один файл содержит записи одного календарного месяца и называется `YYYY-MM.log`; с началом нового месяца файл создаётся автоматически. Email и пароль в лог не записываются.

## Безопасность

Не добавляйте email и пароль в файлы проекта. Они передаются процессу только через GitHub Actions Secrets. Workflow получает право записи содержимого только для сохранения ежемесячного файла лога.

Локальная проверка срока без запуска браузера:

```powershell
python main.py --check-due
```

Команда выводит `due`, если пора выполнять авторизацию, или `not-due`, если 24 часа ещё не прошли.

Локальный запуск авторизации:

```powershell
$env:ASTANAHUB_EMAIL = "you@example.com"
$env:ASTANAHUB_PASSWORD = "your-password"
.\.venv\Scripts\python.exe main.py
```
